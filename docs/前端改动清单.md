# 前端改动清单（127 类 / 28 作物版本）

> 背景：数据集从 38 类 14 作物扩到 **127 类 28 作物**，前端有几处需要跟着改。
> 后端接口已就绪，`ui-rebuild` 只改 `app/web_agent.py` 和样式，不要动后端逻辑。

## 一、必须改（数据不一致）

### 1. 示例按钮只覆盖 6 种作物

现状：`_CROP_EXAMPLES` 取 `LIBRARY` 每作物第一张，限 6 个。
问题：现在有 28 种作物，只显示 6 个（苹果、蓝莓、樱桃、玉米、葡萄、柑橘）。

建议方案（择一）：
- **A. 扩到 8-10 个**：优先中国常见作物（水稻、小麦、番茄、玉米、黄瓜、辣椒、茶叶、苹果、葡萄、柑橘）
- **B. 分组**：按钮下方加「粮食 / 蔬菜 / 水果 / 经济作物」切换
- **C. 保留 6 个 + 「更多」入口**：点击弹出全量作物选择

倾向 A（简单直接），但布局要保证不撑高左栏。

### 2. 图片库覆盖率低

现状：`LIBRARY` 65 条（38 PlantVillage 实验室 + 27 PlantDoc 真实场景）。
问题：127 类里只有 38 类有实验室图，新加的 89 类（水稻/小麦/甘蔗/芒果/茄子/萝卜/棉花/花生/茶叶/辣椒/香蕉/黄瓜/猕猴桃/荔枝）只能靠上传。

需要：图片库覆盖全部 127 类，每类至少 1 张。
- 后端 `web.get_class_images(cls, n)` 已支持任意类别
- 建议按作物分组展示，或加搜索框

### 3. 知识库配图

现状：`_kb_figs()` 取该类 3 张图（2 实验室 + 1 真实场景）。
问题：新类别在 PlantDoc 里没有对应图，会退回 3 张实验室图（可接受）；但如果该类连实验室图都少（如猕猴桃仅 33 张），可能不足 3 张。

需要：不足 3 张时优雅降级（2 张或 1 张也正常显示，不要留空框）。

## 二、建议改（体验）

### 4. 类别数文案

已改成动态 `{_NCLS}`，但请检查是否还有遗漏的硬编码（搜「38 类」「14 种」）。

### 5. 作物分组展示

28 种作物后，下拉框/列表会很长。建议：
- 知识库速查下拉按「粮食作物 / 蔬菜 / 水果 / 经济作物」分组（Gradio Dropdown 支持 optgroup？不支持的话用前缀 emoji 或分组标题）
- 或者加搜索

### 6. 新作物的严重度/病情指数

新加的 89 类，`severity` 字段多数默认「中」。检查 `severity_grade`、`disease_index` 对它们的表现是否正常。

### 7. 评估页

- 混淆矩阵说明从「38 类」改成 127 类
- 图表如果还是旧的 38 类版本，需要提示「图表对应 38 类旧模型」或重新生成

## 三、不要动

- `app/web.py`（后端接口）
- `src/` 下任何文件
- 五个页签的总体布局（高度约束已调好）

## 四、验收标准

1. 五个页签都能正常打开，无控制台报错
2. 示例按钮任一可用，点击后能载入图片
3. 图片库能选到新作物（如水稻、茶叶、黄瓜）
4. 知识库速查切到新类别（如水稻稻瘟病），有 1-3 张图正常显示
5. 页面高度不因改动撑破（诊断页 ≤ 1000px，AI 页 900px）
