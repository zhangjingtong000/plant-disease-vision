## 透镜一：角色巡检

本系统无权限系统、单一使用者，故「角色」按**使用者场景**定义。

### 1.1 演示现场的目标用户（主角色）

动线：打开 → 载入示例 → 诊断 → 病斑定位 → 症状防治 → 导出 PDF → 批量 → 评估 → 问答 → 更多（历史）。

- **PDF 会把「拒识」这件事悄悄撤销**：阈值调到 0.9 演示「系统不硬下结论」是加分动作，但接着点「导出 PDF」，拿到的报告写着「番茄 晚疫病 85.6% 置信度」，全文检索「复核」为假（pypdf），只在热力图说明里出现过一次「阈值分割」—— 现场若被要求「打开 PDF 看看」，等于自证前后矛盾 🔴 **H1**
- **改模型不重诊断就导出，报告换成另一个模型的结论**：页面卡写「诊断结果 · ResNet50（无法确定）」，把下拉改成 MobileNet 再点导出 → PDF 变成「mobilenet_v3_large / 96.1% 置信度」🔴 **H2**
- **同一张图的病斑比例，页面 7.9%、PDF 5.2%**（`scan/F02_lesion.png` vs `诊断报告_20261117_112736.pdf`）—— 评审者若并排看，问一句「哪个对」就下不来台 🔴 **H4**
- 演示完拒识忘记把滑块调回：阈值 0.9 保留，下一次诊断继续拒识，页面上没有「恢复默认」出口 🟢
- 「导出 PDF」实测 15–22 s、「病斑定位」8–14 s，**全程只有按钮转圈，没有进度文字**，演示时冷场 🟠 **G12**
- 演示「38 类全覆盖」：图片库可点，✓
- **README 写「10/9 个功能模块」，系统实际是 5 个页签**（「统计面板」并入更多、「模型对比」并入评估）——按 README 讲会被现场「数页签」数穿 🟢 S10
- 演示「可解释性」时找不到遮挡实验（PLAN 五承诺的第三件），也找不到退化鲁棒性曲线 🟠 **G6**
- 已办✓：单张诊断 → Top-5 → 防治 → PDF 主链闭合；批量执行 0.2 s（模型热态）

### 1.2 评审视角（对着技术说明功能表逐条找入口）

动线：读功能表 → 系统里找入口 → 问数字出处 → 问边界。

- 技术说明若写了「遮挡实验 / 退化鲁棒性 / 模型速度对比」，**系统里一个入口都没有**：评估页 14 个图位只挂了 5 张同分布图 + 7 张跨域图，页面全文检索「退化 / 遮挡 / 鲁棒 / 延迟 / FLOPs / 吞吐 / 耗时」全部为假（`scan/B07_eval_resnet.png`，实测输出）🟠 **G6 / G7**
- 指标卡「98.61%」没有出处、没有生成时间、没有指向哪个 JSON；`outputs/metrics/` 里却有 `eval_*.json`、`benchmark.json`、`occlusion_*.json` 一堆可引用的原始数据 🟢 **S7**
- 问「你这个 12.3% 是病情指数还是病叶率」→ 系统只有单叶面积占比，自造「轻微/中等/严重」三档，与地方标准的 0/1/3/5/7/9 级和病情指数公式对不上 🟠 **G11**
- 问「这份报告交给农户，他知道是哪块地、什么时候拍的吗」→ PDF 无地块/品种/送检人/拍摄时间 🟠 **G10**
- 已办✓：跨域局限说明写得比多数同类项目克制（`render_xd_limitations`），这一节可以直接讲

### 1.3 第一次接触的农户（看不懂术语，只想知道「打什么药」）

动线：拍一张 → 知道是什么病 → 知道怎么治 → 存下来 / 给人看。

- 结果卡上并列「置信度 85.6%」「病原类型：卵菌」「危害程度：极高」「推理耗时 860 ms」——**把模型内部参数直接摆给终端用户**，农户不知道「置信度」是什么，也不知道该不该信 🟠 **G13**
- 没有一句「人话结论」（如「番茄晚疫病，当前叶面病斑 7.9%，属轻发生，建议先控湿再用药」），信息全在结构化字段里 🟠 **G13**
- 知道病名后想「打什么药、多少倍、隔几天」→ 已知项（防治 3 条话术），不重复
- 想找当地植保站问一句 → **系统没有任何人工通道**；拒识卡只写「建议重拍后重试或人工判断」，没说找谁（对照：耘眼详情页底部直接给专家咨询电话）🟠 **G9**
- 想回看上次的诊断 → 历史页不含图片、不含病斑比例、不含地块 🟠 **G1/G4**

### 1.4 农技推广员（一个村 30 张照片，批量 + 汇总上报）

动线：收 30 张照片 → 批量识别 → 挑出高风险 → 汇总成一份材料 → 上报/回访。

- 批量跑完只有一张表 + 一个 CSV，**没有汇总报告**（没有「本批 30 张中高危 X 张、涉及作物分布、建议优先处置清单」）🟠 **G3**
- 批量结果**不进识别历史**（`web.py:316-344` 无 `_log_history`；实测清空历史后跑批量，`history.csv` 仍未生成）→ 第二天想回看这批，查不到 🟠 **G1**
- 表里「照片」列只有文件名，**同名文件两行长得一模一样**（实测 4 行里两组 `test_0000.jpg`），详情下拉也是两个同名项，无法判断点的是哪张 🟠 **G2**
- 想按「待复核」筛出高风险条目 → 批量表无筛选、无排序 🟠 **G2**
- 想算「本批病叶率 / 发生程度」→ 没有 🟠 **G11**
- 已办✓：图片库可连续点击追加、可清空已选、CSV 立即落盘（UTF-8-SIG，Excel 可直开）

## 透镜四：生命周期反推

### 4.1 主链（⚠ = 缺口）

拍摄 → 上传 → 识别 → 看结果 → 看防治 → 定位病斑 → 导出报告 → 归档 → 复诊/追踪

- 拍摄 ⚠ **无图像质量自检**（暗/糊/主体过小不会提示，只在二元「像不像叶片」上判死）
- 上传 ✓（单张/批量、图片库、示例）；⚠ 无 EXIF 时间/地点
- 识别 ✓（三模型、拒识）；⚠ 只看 Top-1 置信度，不看 Top-1 与 Top-2 的间隔
- 看结果 ✓；⚠ 术语面向工程师，无一句人话结论（G13）
- 看防治 ✓（内容深度=已知项）
- 定位病斑 ⚠ **三处阈值三种结果**（单张 0.5 / 批量=滑块值 / PDF 0.6）
- 导出报告 ⚠ **绕过拒识（H1）、模型串台（H2）、缺归档要素（G10）**
- 归档 ⚠ **无报告列表、历史不含图片与报告路径、批量不入历史**（G1/G4）
- 复诊/追踪 ⚠ **系统里没有「病例/植株/地块」这层实体**，只有一张张孤立的图；同一叶片隔 7 天再拍，无法与上次对比（G11/N2 是其前置）

### 4.4 硬伤细节（代码证实，可直接讲 3 分钟）

#### H1 · 导出 PDF 完全绕过拒识（页面说「不下结论」，报告盖章下结论）

> 多透镜命中：透镜一（评审视角现场并排对比）、透镜二（「诊断报告」实体无查询无归档）、透镜四（导出环节无守卫）。

- 现状：`on_diagnose` 低置信度返回 `render_rejected`（`web_agent.py:922`，拒识卡文案「系统不强行给出结论」），但「导出 PDF」是 build_ui 里**静态按钮**，没有任何禁用逻辑；`on_pdf(img, model_name)`（`web_agent.py:955-962`）只接图片与模型名，完全不接 `thresh` 也不接 `last_info`；`web.make_pdf`（`web.py:509`）内部重新 `infer` 后直接出结论。
- 实测：阈值 0.90 → 页面「置信度不足 / 无法确定」（`scan/G01_low_conf.png`）；点导出 → `诊断报告_20261117_112815.pdf` 正文「番茄 / 晚疫病 / 85.6% 置信度」，pypdf 全文检索「复核」= False、「建议人工复核」= False（「阈值」仅出现在「阈值分割」这句图例说明里，与本条无关）。
- 为什么错：README 功能表与界面使用说明都把「低置信度拒识」当卖点；报告是对外交付物，它推翻了系统的核心承诺。
- 正确做法：拒识态 `pdf_btn` 置灰（`gr.update(interactive=False)`）并在 `on_pdf` 里再守一道；若允许生成，报告首页必须带「置信度 85.6% < 阈值 90%，本报告仅作参考、不作结论」的提示条，并把阈值写进结果块。
- 补测：阈值 0.95 + 一张低质量图 → 断言页面无类别、PDF 按钮 disabled、PDF 不存在或含水印。

#### H2 · PDF 用「当前下拉模型」重算，报告与页面不是同一次诊断

- 现状：页面结果卡冻结在「诊断结果 · ResNet50」，但 `on_pdf` 取的是**当前** `model_dd` 值；`make_pdf` 重新推理。用户改下拉（未点诊断）再导出，报告即换模型。
- 实测：页面「ResNet50 · 无法确定」→ 下拉改 MobileNet-V3 → 导出 → `诊断报告_20261117_112821.pdf`：「识别模型 mobilenet_v3_lar / ge」（换行断裂）/「96.1% 置信度」（`scan/G03_pdf_after_switch.png`）。
- 为什么错：一份带编号的报告对应一次诊断，模型是不可分割的属性；重新推理还会让「推理耗时」字段失真（页面 860 ms → PDF 57 ms）。
- 正确做法：`on_diagnose` 把 `(info, top5, elapsed, model_name, thresh)` 冻结进 `last_info`，`on_pdf` 只消费它，**不再推理**（顺带把 PDF 生成时间从 15–22 s 降到 2–3 s，G12 一并缓解）。
- 补测：诊断 → 改下拉 → 导出 → 断言 PDF 的模型名与页面一致。

#### H4 · 病斑面积三处口径（0.5 / 滑块值 / 0.6），同一张图三个数

- 现状：单张 `on_locate` 已固定 0.5（`web_agent.py:938`，注释已写「不再与拒识阈值混用」）；**批量 `on_batch_locate` 仍把 `thresh` 传进 `locate_view`**（`web_agent.py:1031`）；**PDF `make_pdf` 固定 0.6**（`web.py:522`）。
- 实测①（批量详情，同一张图，只动滑块）：阈值 0.90 → 「病斑占叶面 1.2% 轻微」；阈值 0.30 → 「病斑占叶面 49.1% 严重」（`scan/H05_batch_lesion_09.png`、`scan/H06_batch_lesion_03.png`）。
- 实测②（页面 vs PDF，同一张图）：页面 7.9%（`scan/F02_lesion.png`）vs PDF 5.2%（`诊断报告_20261117_112736.pdf`）。
- 为什么错：这正是已知项「阈值一物两用」的**未修完的另一半**——单张修了，批量与 PDF 漏了；而且三处硬编码不同值，修完单张反而制造了新的不一致。
- 正确做法：在 `web_agent.py` 顶部定义 `LESION_THRESH = 0.5`，`on_locate` / `on_batch_locate` / `make_pdf` 三处统一引用，并在病斑卡注明「分割阈值固定 0.5」。
- 补测：同一张图，滑块 0.3/0.6/0.9 三次定位 → 断言比例完全相同；页面与 PDF 比例相同。

#### H3 · 批量详情没跟上「真拒识」（同族规则不对称）

- 现状：单张低置信度走 `render_rejected`（不给类别）；批量详情 `on_batch_detail` 仍调 `render_result(..., low)`（`web_agent.py:1021`）——只换徽章。
- 实测：阈值 0.90，批量表第 2 行「待复核 87.75%」；点开详情 → 「黑腐病 87.7% / 建议人工复核」**照给类别**；同一阈值下把这张图放到单张页诊断 → 「无法确定」（`scan/I01_batch_detail_second.png`）。
- 为什么错：同一个系统、同一个阈值、同一张图，两个页面给出两种结论；评审视角只要走一次就会问「到底哪个是规则」。
- 正确做法：`on_batch_detail` 与 `on_diagnose` 共用同一分支函数（抽 `build_diagnosis_view(img, model, thresh)`），批量详情内也允许「看候选 Top-5 但不给结论」。
- 补测：阈值 0.9 + 一张 0.8x 置信度的图，断言批量详情与单张页文案一致。

#### H5 · 历史「删除指定记录」删错行（新功能，服务尚未加载，上线前必须拦下）

- 现状：表格 `#` 列来自 `render_history_table` 里 `all_data = list(reversed(rows[1:]))` 后的行号（**#1 = 最新**，`web_agent.py:800`）；而 `web.delete_history` 按 `enumerate(body, 1)` 在**原始正序** body 上删除（`web.py:455`），且**不接收筛选条件**。UI 提示语还写着「输入要删除的序号，如 1,3,5（对应表格 # 列）」（`web_agent.py:3072`）。
- 实测（直接调用后端函数，`docs/screenshots/scan/_py_scan_k.py` 输出）：
  - 5 条记录（记录1 最旧 … 记录5 最新），表格 #1 = 记录5；输入「1」→ 实际删掉 **记录1**，剩 记录2/3/4/5。
  - 筛选「苹果」后视图只有 1 条（苹果），输入「1」→ 实际删掉 **番茄-记录A**（筛选视图外的行）。
- 为什么错：不可恢复的删除 + 序号反转 + 忽略筛选 = 用户以为删了 A，实际删了 B。这是本轮发现里唯一的「数据被错误删除」类硬伤。
- 正确做法：`delete_history` 改接收**已展示行的稳定标识**（时间+类别+置信度的复合键，或每行加 UUID 列），或至少统一为「倒序 + 筛选后」的同一视图索引；删除前写 `history.csv.bak` 并弹二次确认。
- 补测：造 5 条 → 删 #1 → 断言删掉的是最新那条；筛选后删 #1 → 断言删的是筛选结果第 1 条。
- 备注：该功能对应已知项「历史不能删除」的修复，目前运行中的服务（11:26 启动）尚未加载此 UI，属**上线前拦截**。

## 结论

本次四透镜共得：**硬伤 5 处、高价值 14 处（G1–G15，其中 G8 已降入 🟡）、顺手 10 处、暂缓 8 项**。其中 H1/H2/H3/H4 与 G1/G2/G4/G5/G6/G7/G12/G15 有运行时实测证据，H5 来自对尚未上线新功能的后端函数级验证，其余来自代码与文件核对。

最该先补的三件事，按「演示会被问穿」排序：

1. **H1+H2+H4：报告与页面必须是同一次诊断的同一组数字。** 现在同一个流程产出三套数字（页面 7.9%、PDF 5.2%、批量滑块 1.2%–49.1%）和两个模型归属。这不是体验问题，是「系统说的话自己都不认」——评审只要并排看一次就成立。修法很轻（三处统一常量 + `on_pdf` 复用冻结结果），合计半天。
2. **H5：历史删除删错行。** 这是本轮唯一的「数据被错误删除」类缺陷，且正好卡在已知项「历史不能删」的修复上——上线前必须拦下，否则「修好一个功能、引入一个数据事故」。
3. **G1+G4：批量不进历史、历史页显示启动快照。** 演示动线的最后一步「我诊断过的记录在哪」目前是断的：批量记录不存在，单张记录要手动点刷新才出现。两个都是 0.5h 级。

建议顺序：**H5 → H1/H2/H4/H3（半天，一次性把「一致性问题」清干净）→ G1/G4/G5（1h 级，让回看闭环）→ G7/G6（评估页补齐承诺与速度维度，演示加分）→ G10/G11/G2/G3（农技闭环，按余量）→ G9/G12/G13/G14/G15 → S 系列一次性清掉**。

要写进技术说明「已知边界」的：38 类病害不含虫害/缺素/物候；无账号与云端，单机单用户；不承担专业化服务组织的档案合规义务；病情指数为简化版（单叶面积占比映射 + 批量聚合），非田间多点取样。
